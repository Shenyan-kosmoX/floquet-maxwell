# 一起改进 Floquet–Maxwell

欢迎通过问题反馈、代码、案例和文档参与项目。研究工具常常在实际使用中变得更好：一次难以复现的计算、一条含义不清的单位说明，或一个新的物理对照，都值得记录下来。

## 报告问题

在仓库的 Issues 中说明想研究的问题，并尽量附上：

- 使用的版本或 commit、Python 和主要依赖版本。
- 能重现问题的最小配置、运行命令与相关输出。
- 实际结果、预期行为，以及判断预期的依据。

涉及科学结果时，几何、材料、调制、单位和观测量往往比完整日志更有帮助。可以先描述已经观察到的现象；如果原因还不清楚，一起缩小问题范围也是有价值的工作。

## 提交改进

小幅修正可以直接提交 Pull Request。新增接口或较大的模型扩展，欢迎先用 Issue 介绍用途、输入输出和一个示例，让讨论尽早围绕实际问题展开。

通用方法放在工具箱模块中，论文特定的参数、运行脚本和绘图放在案例层。修改实现时补充与变化相称的检查：例如解析极限、独立计算、已有案例回归，或能揭示问题的反例。文档修订通常只需检查内容与链接。

PR 说明应让读者看清改动解决的问题、使用方式和检查结果。几何、材料、辐射近似、观测量或容差发生变化时，请说明原因，并让原结果仍能对应到原配置。

## 增加一个研究案例

可参考[张量调制案例](../../cases/jin2025-tensor/CASE.md)及其 [case.yaml](../../cases/jin2025-tensor/case.yaml)。一个便于别人接续的案例应包含：

- 清楚的问题、模型、参数来源和适用条件。
- 环境、运行命令、输入取得方式与输出位置。
- 与目标观测量有关的验证，以及结果和结论的对应关系。
- 已知差异、敏感性和下一步值得检查的问题。

将新案例登记到 [research.yaml](../../research.yaml)，让读者和自动检查都能找到它。已有报告可以直接引用，无需在不同文档中反复复制同一组数据。

文献比较中的差异也有研究价值。请保留实际参数与原始结果，区分数值敏感性、模型近似和来源不确定性；新的解释应有能够区分这些可能性的证据。

## 署名与许可

自有代码按项目的 [MIT 许可证](../../LICENSE)接收和分享。引用或改编上游代码时，请保留原版权、许可和来源，说明具体修改。贡献第三方数据、图片或模型时，一并提供来源及使用条件。

感谢每一位愿意让方法更清楚、计算更可靠的人。文档中的一句澄清和代码中的一个修正，同样可以成为别人继续研究的起点。
