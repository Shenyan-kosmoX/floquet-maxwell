# 实际极化源的初始化检查

结论：**原源回调没有发现内部坐标、相位或幅度错误。** Meep 的 `get_source` 与 `get_array` 数组同形，不等于它们位于相同采样点。直接按共同中心坐标解释原始源数组会产生虚假的大误差。

本检查只初始化计算，不推进时间。几何、网格、源函数、源体积和原极化响应算例一致。独立构造常数、`x+iy`、`z` 源，利用返回幅度识别实际的存储坐标与边界权重。没有使用动态响应作拟合。

在三维、分辨率 24 的当前模型中，返回源分量相对 `get_array_metadata` 坐标的位移为：

| 分量 | 位移/网格步长 |
|---|---|
| Ex | (0, −1/2, −1/2) |
| Ey | (−1/2, 0, −1/2) |
| Ez | (−1/2, −1/2, 0) |

独立坐标探针误差低于 1.5×10⁻¹⁶ a。仅在远离源体边界的内部检查，实际源与按上述 Yee 坐标求值的 `−iωQ` 相对误差为 7.9×10⁻¹⁶、3.0×10⁻¹⁵。再加入由常数源独立确定的源体边界权重后，两个完整返回源数组与预期精确相同。

`summary.json` 中保留的原始中心比较差值不是注入错误。掩膜外出现的源切片值也不能不经坐标还原就解释为真实源泄漏。

这项检查排除了一个具体实现假设，但没有建立共同中心场的 `Q†W` 投影与 Yee 电流注入之间的严格离散伴随关系。静态场等待时间、场插值、源体权重和界面模型仍可能影响光学定理与互易残差。未修改、对称化或缩放任何已测得的 R/T，也没有用本检查证明谐波或全波收敛。

依据为 Meep 官方 [v1.35.0/src/array_slice.cpp](https://raw.githubusercontent.com/NanoComp/meep/v1.35.0/src/array_slice.cpp) 的 `get_source_slice_chunkloop`：源码从 `s.index_at(npt)` 取得分量的内部数组索引，再用 `fc->gv.iloc(Dielectric, chunk_index)` 为该源幅度安排切片存储位置，不插值幅度到场中心。本地源文件（历史材料 `meep_array_slice.cpp`；见[发行说明](../../../../../docs/RELEASE.md)）已经保存。
